# Phase 9: Full System Integration + UI

## Integration Overview
The complete Phase 1-8 pipeline has been successfully integrated into a cohesive end-to-end application. The `FactCheckingPipeline` class acts as an orchestrator, connecting the modular components cleanly without duplicating any logic or circumventing the cache mechanisms. 

The pipeline structure flows as follows:
1. **Retrieval**: `EvidenceRetriever` fetches `top_k` documents using hybrid BM25/Dense matching.
2. **Verification**: `ClaimEvidenceVerifier` determines the actual fact-checking verdict and probabilities.
3. **Attribution**: `EvidenceExplainer` computes SHAP and LIME scores for each evidence piece.
4. **Intervention**: `EvidenceIntervener` computes mathematical influence ($\Delta P$) using Leave-One-Out.
5. **Conflict**: `ConflictDetector` assigns SUPPORTING/REFUTING/NEUTRAL roles and checks for mixed signals.
6. **Stability**: `StabilityAnalyzer` measures the rank robustness (Spearman) of the attribution.
7. **Fuzzy Assembly**: `FuzzyEvidenceEngine` combines the piece-level scores (relevance, attribution, intervention) with the global scores (conflict, stability) into human-interpretable metrics.
8. **Final Summary**: The orchestrator produces a natural-language description separating the *Verdict* from the *Explanation Robustness*.

## UI Details
The user interface was built using **Streamlit**. It offers a clean, hierarchical view:
1. **Claim Input**: Simple text box.
2. **Verdict**: Prominent display of the fact-checking conclusion.
3. **Retrieved Evidence**: Expandable cards showing the exact source text.
4. **Explanation & Attribution**: A clear table breaking down each evidence piece's SHAP/LIME influence, $\Delta P$, and Support/Refute role.
5. **Global Explanation Robustness**: Highlight boxes displaying the overall stability and conflict detection scores.
6. **Evidence / Explanation Reliability Metrics (Fuzzy)**: The nuanced fuzzy output for each evidence piece.
7. **Final Summary**: The human-readable conclusion generated by the orchestrator.

*Critical UI Principle Enforced:* The layout explicitly distinguishes between the "FACT-CHECKING VERDICT" (from the NLI model) and the "EXPLANATION RELIABILITY" (from the causal/fuzzy layers), ensuring the user does not conflate explanation stability with factual truth.

## Data Flow
Evidence traceably flows across all modules via `evidence_id`. The pipeline extracts lists, passes them to independent evaluation modules, maps the results into dictionaries via `evidence_id`, and safely merges them into the unified `EvidencePipelineResult`.
